## 调用边界

仅在用户明确调用 `$evidence-calibration`、要求使用本 skill，或要求执行本 skill 的完整核验流程时启用。仅提到名称、询问用法、检查或修改本 skill，不算调用。

不根据任务主题自动启用。研究、方案比较、事实查证、代码修改与测试、常规数据分析等任务，即使需要证据，也按原任务要求执行；不自动叠加本 skill、扩展成 P1 至 P7 或生成核验台账。

`agents/openai.yaml` 中的 `policy.allow_implicit_invocation: false` 用于支持该策略的宿主。其他 agent 仍须遵守上述调用边界。用户明确调用后，再执行下面的流程。

## 任务边界

执行下面的 input-process-output 流程，产出有证据支持的判断及可推进的下一步。适用于论文、网页、文档、数据、代码、测试、访谈和日志。使用同一流程，但按任务风险调整核验力度。

请求分析不授权实施。不要自行付费、外部写入、运行高成本实验或调用未经授权的子 agent。每次任务的文件产物集中在新建的独立交付目录，项目已有文件默认只读。本 skill 降低错误风险，不保证消除幻觉。

## Input：形成任务规格

从用户请求和现有材料填写下表。缺项先自行查阅，只有会改变结论或授权范围的选择才问用户。不要要求用户另填一份表。

| 输入字段 | 要确定的内容 |
| --- | --- |
| 目标问题 | 要回答什么，或要比较哪些选择？什么结果算完成？ |
| 当前任务条件 | 对象、数据、环境、时间或版本，以及已知约束。 |
| 已有材料 | 用户提供的文件、来源、候选、结论；标明哪些只是用户给定假设。 |
| 允许范围 | 可搜索的渠道、可访问材料、可执行检查及禁止事项。 |
| 决策后果 | 本轮是解释、筛选、推荐验证，还是支持实际采用？错误后果及可逆性。 |
| 交付与预算 | 输出格式、独立交付目录的根位置、时间或工具限制；未指定时采用下方目录规则，不自行承诺穷尽检索。 |

中间产物为 `Task spec`。后续搜索、核验和推荐都对照它，不因查到新材料便擅自扩展任务。

执行前阅读 [记录格式、抽查规则与交付模板](references/audit-protocol.md)。简单任务使用精简记录；大量证据必须保留论断与来源的对应。

## Process：按步骤执行

开始前在安全可写位置创建本次独立交付目录，记录其绝对路径。全部新增报告、台账、日志、下载材料、检查脚本及预览都写入该目录。读取现有材料时保留原始位置，不移动、覆盖或修改输入文件，也不更新项目现有日志或索引。

### P1. 将目标拆成可核验的论断

列出回答目标问题需要证明的内容，为每个论断分配 `C` 编号。标明是事实、效果、适用性还是推荐依据。按“如果它错了，会改变什么”分层：改变主结论、候选排序、决定性排除或行动安全的标为 `critical`，其余为 `secondary`。新证据改变论断时更新，不固定第一轮分类。

产物为 `Claim map`，包含论断、用途、分层及理由。完成条件是主要结论和决定性排除都能对应到论断；不能只审查支持推荐的内容。

### P2. 搜索并建立来源清单

从问题和领域用语搜索，再追查具体候选。对优先候选分别找原始依据、独立使用或验证、限制及替代方案。选择与论断相匹配的材料，不套用统一的期刊、年份或来源数量门槛。

为来源分配 `E` 编号，记录真实位置、版本、发现途径、实际读取范围及共同原始来源。摘要、片段和二手总结可以发现线索，不能冒充已读原文。按共同原始证据去重，不将转述数量计为独立验证。

产物为 `Source register` 和 `Search log`。每条优先路线都应记录查过哪些支持、限制与替代线索，以及还缺什么；不要求必须搜到相反结果。

### P3. 逐项核验关键论断

核验全部 `critical` 论断及其必要的 `C–E` 对应。打开实际来源，读取足以判断的原始上下文，记录具体位置与依据，再检查对象、方向、程度、条件和时间范围。必要时核对原始数据、代码或实际测试输出。

逐项写明来源直接支持什么、agent 推断了什么、当前任务条件检查了什么。使用 `supported`、`partial`、`contradicted`、`unverified` 状态，分别记录转述核验与任务适用性；不能用“可信”概括全部。

产物为 `Evidence ledger`。来源缺失或只读摘要的关键论断标为 `unverified` 并进入 P5，不计入已完成核验。不能把相关性升级成因果性、可模拟升级成有效、特定条件升级成普遍适用。

### P4. 抽查其他论断，发现问题则扩大核验

按参考文件的默认规则，对 `secondary` 的 `C–E` 对应分层、定向检查并随机抽查。逐条执行与 P3 相同的核验，记录抽中的编号、错误类型和修订。

发现问题后定位失败来源或处理批次，扩大核验；重复出现同类问题、影响边界不明，或错误改变主结论时，全查受影响范围。复核候选排序，不只改一句话。

产物为 `Audit log`，列出总体、已查、未查、问题和扩大范围。完成条件是规定样本已经核验、发现问题已经修正；抽查通过不能将未查条目改为已核验。

### P5. 针对决定性缺口补查

将影响选择的缺口分配 `G` 编号，写明补到什么结果会改变判断。按缺口选择下一步：追原始引用、换检索词、查独立应用、找合法替代版本、检查本地材料，或做已授权的只读诊断／可逆小测试。

每次记录“动作、结果、缺口是否缩小、下一步”。不可访问不等于不适用，未做当前任务实测不等于不能推荐验证。候选确有条件冲突时查替代路线，不停止全部工作。

产物为 `Gap log`。缺口应被补足、经核验导致调整判断，或附具体受阻依据及替代动作。只写“待核验”“需要更多研究”不算完成。预算或授权不足时转为阶段交付，不虚构已完成。

### P6. 比较选择并给出有条件的判断

对每个主要候选列出已支持的能力、限制、当前条件冲突、未查条件及未测效果。比较同一任务目标下的证据，不用一个总分掩盖决定性冲突。无需在当前任务中证明效果之后才推荐下一步验证。

提出当前首选及合理备选，或说明应先做哪个区分测试。每项推荐写出依据、成立条件、最小下一步和会推翻它的结果。明确推荐的是 `investigate`、`test`、`adopt` 还是 `defer`；推荐测试的证据不能自动支持正式采用。

产物为 `Decision brief`。完成条件是用户知道现在优先推进什么、为什么、验证什么。证据不能支持选择时，给出具体取证动作，不强行排名，也不以全部“待核验”结束。

### P7. 检查夸大与过度保守，决定是否交付

从原始材料复查关键结论，重点检查“有效、成熟、普遍、可以直接使用、无法、不适用、无证据”等表述。分别检查超出来源的结论和没有具体依据的排除。发现错误则回到相应步骤，更新台账与推荐。

执行以下交付检查。

- 主要结论与推荐都有可定位的依据，推断和未完成核验就近标注。
- 关键论断已逐项处理，抽查问题已修正；未完成部分不写成完成。
- 决定性缺口有实际补查记录，暂缓或排除有具体理由。
- 已给出比较判断和下一步，未编造置信概率或验证结果。

全部满足且新证据不再改变关键判断时交付。达到时间、预算、权限或访问边界时，可以交付阶段结果，但注明哪些检查未完成及其影响。另一段 AI 的同意不是原文核验；独立复核只有实际进行且接触原始材料时才可报告。

## Output：在独立目录交付

优先使用用户指定的交付根目录。未指定时，在当前工作区的 `deliveries/evidence-calibration/` 下新建 `YYYYMMDD-HHMMSS-task-name/`，日期与时间采用实际执行时间，任务名使用简短英文。目标已存在时增加后缀，不覆盖前轮产物；没有安全可写位置时先问用户。

每次交付目录按参考文件中的结构组织，默认包含任务规格及下列三个产物。用户指定其他格式时仅调整本目录内的文件，不向项目其他板块分散写入。

| 产物 | 必须包含的内容 |
| --- | --- |
| `Decision_Brief.md` | 当前判断、推荐层级、首选／备选或区分测试、关键依据、成立条件、推翻条件和下一步。 |
| `Evidence_Ledger.json` | 论断及来源清单、`C–E` 对应、来源位置、实际读取范围、原始依据、转述核验、任务适用性、推断边界和缺口。 |
| `Search_and_Audit_Log.json` | 实际搜索／检查动作、同源去重、抽样方式与编号、覆盖量、错误及修订、扩大核验范围、`G` 缺口的处理与停止原因。 |

小任务精简记录，大任务保留完整对应关系。正文只呈现判断、关键证据、影响选择的缺口和下一步，结束时给出交付目录和主报告链接。除用户明确另行授权外，目录之外不产生新增或修改文件。检查工具会写缓存或临时文件时，将其工作目录和输出路径设在本目录的 `_work/`，无法安全隔离时不运行该检查。不得自行清理已有文件。

用户明确要求仅在对话中回答、不保存文件时，不落盘。文件交付目录不可用时，如实说明限制并提供对话中的阶段结果，不将文件偷偷写到别处。

交付中说明“关键论断完成多少／总共多少、其他对应核验多少／总共多少、仍未完成什么”。这些是实际覆盖量，不是报告正确率。用户无需逐一核查全部材料，但仍应能直接打开关键来源位置并看到需要人工决定的具体事项。
