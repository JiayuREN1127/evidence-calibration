## 使用方式

执行主文件的 P1 至 P7 时使用下列字段与模板。默认格式按下方交付结构保存，用户可指定其他格式。小任务精简记录，大任务可以读取项目已有日志，但新增记录只写入本次独立交付目录。字段中的空值表示尚未取得，不准补造。

## 独立交付目录

默认结构如下。只创建任务实际需要的可选子目录，不预建空目录。

```text
deliveries/evidence-calibration/YYYYMMDD-HHMMSS-task-name/
  Task_Spec.yaml
  Decision_Brief.md
  Evidence_Ledger.json
  Search_and_Audit_Log.json
  sources/                    仅放本轮新取得的材料，按需创建
  _work/                      检查脚本、测试输出、预览及临时文件，按需创建
```

`Evidence_Ledger.json` 的顶层字段为 `claims`、`sources` 和 `claim_evidence_links`，对应下文的 Claim map、Source register 及论断与来源的对应记录。`Search_and_Audit_Log.json` 的顶层字段为 `search`、`audit`、`gaps` 和 `stop_reason`，对应搜索动作、抽查及扩大核验、缺口处理和停止原因。空数组只表示没有条目，不能代替未做检查的说明。

用户指定交付根目录或格式时，在其下面保持一次任务一个新目录。检查目标不存在，再创建；有同名目录就增加后缀。原始材料留在原处，在来源记录中保存绝对路径或可复查的链接；无需为了集中交付重复复制原始大文件。

交付前解析 YAML 和 JSON，检查 Markdown 渲染、目录内链接及来源定位。核对本次实际写入位置均在交付目录中，或属于用户另行明确授权的目标。不移动原文件，不回写项目已有报告、索引或日志，不以清理临时文件为由删除已有内容。

## 输入记录模板

```yaml
task_spec:
  goal: null
  completion_criteria: []
  current_conditions: []
  provided_materials: []
  user_assumptions: []
  permitted_actions: []
  prohibited_actions: []
  decision_type: null
  consequences_and_reversibility: null
  output_format: null
  delivery_root: null
  delivery_directory: null
  budget_or_time_limit: null
```

从请求中填写，不要求用户逐项提供。未指定预算不代表无限检索，未指定行动权限不代表可以实施。`delivery_root` 未指定时采用主文件的默认位置；创建目录后将实际绝对路径填入 `delivery_directory`。用户明确不要过程文件时在对话中说明，不落盘。

`Claim map` 为每条 `C` 记录 `claim_text`、`claim_type`、`decision_role`、`priority` 和 `priority_reason`。`claim_type` 分为事实、效果、适用性、推荐依据；`priority` 为 `critical` 或 `secondary`。引用、候选和结论增加时更新此表。

## 记录论断与来源的对应

先建立 `Source register`，为每条 `E` 记录 `source_location`、`source_type`、`version_or_date`、`discovery_route`、`read_scope`、`root_source_id` 和 `processing_batch`。共同原始证据使用同一个 `root_source_id`；查不清同源关系时标明未知，不假设独立。

再建立 `Evidence ledger`。以一条论断与一条来源的对应为记录单位，最低包含以下字段，允许沿用项目字段名。

| 字段 | 内容 |
| --- | --- |
| `claim_id / evidence_id` | 对应的 `C` 和 `E` 编号，能追到论断及来源清单。 |
| `locator / read_scope` | 页码、章节、代码行或测试命令，以及实际读取／测试范围。 |
| `raw_support / limitations` | 最短必要摘录或准确结果，以及不能省略的限制。 |
| `support_status / reason` | 转述是否得到支持，采用下方状态并说明原因。 |
| `task_fit / checked_conditions` | 当前条件是否满足，列明实际检查及尚未检查的条件。 |
| `inference_boundary` | 来源事实到当前判断之间增加了什么推断？ |
| `gap_ids / corrections` | 关联的 `G` 缺口、已作修正及影响。 |

一个来源可支持多个论断，同一论断也可依赖多个来源。保持对应关系，不以“论文已读”代替“这些论断都成立”。原始依据未取得时留明缺口，不从已有 AI 笔记补写所谓原文。

长文档只读相关章节可以完成特定论断的核验，但应读足上下文。页码注明 PDF 页序还是出版页码。网页记录适用版本或日期。运行输出区分实测、模拟和示例，链接区分来源位置与核验产物。

## 核验状态与处理动作

| `support_status` | 判定与下一步 |
| --- | --- |
| `supported` | 读到足够上下文，来源支持论断的对象、程度与条件。保留该论断，不自动推导任务适用或效果成立。 |
| `partial` | 来源仅支持较窄的内容。缩窄表述，并为缺少的部分建立 `G`。 |
| `contradicted` | 来源与该转述相冲突。更正或删除该转述，保留冲突记录，并复核推荐。 |
| `unverified` | 未读取必要内容，或条目尚未抽查。保留发现线索，不能作为已核验事实。 |

`task_fit` 另记为 `met`、`unchecked`、`conflict` 或 `not_applicable`。分别表示已检查的必要条件满足、仍有必要条件未查、已查出条件冲突、该论断不涉及任务迁移。`met` 不表示当前任务效果已被证实。

来源之间冲突时逐条保存，不用“多数支持”抹去冲突。比较对象、时间、条件和证据质量后形成推断；尚不能解释的冲突写进推荐条件。可信来源中的真实结果不因反对当前首选就被删除。

## 分层抽查与问题扩大

先将全部关键论断及其必要证据移入逐项核验范围，再对其余条目抽查。抽样以“论断与来源的对应”为单位，并保留来源类型、处理批次、语言或格式等分组信息。

用户未指定抽查方案时，使用以下启动规则。默认数量用于开始检查，不是统计上保证准确率的样本量；高风险任务应提高力度。

1. 将剩余 `secondary` 对应按来源类型与处理批次分层。总数不超过 10 时全部核验。
2. 总数超过 10 时，每个非空层至少查 1 条。优先选择跨领域推断、OCR、换算、二手转述或强程度词等易错条目，记录定向选择理由。
3. 再从尚未查的条目中随机抽取最多 5 条；不足 5 条则全查。记录实际编号、抽样工具及可取得的随机种子。无随机工具时使用预先确定的系统抽样规则，并标明不是随机抽样，不凭印象挑选。

用户预算不足以完成默认方案时，报告未覆盖层及影响。不能用其他层的通过结果替未查层背书。任务指定其他方案时，记录采用的方案及理由。

发现问题时按以下逻辑处理。

1. 定位来源读取、提取、转述或推断中的失败环节。
2. 确定同源、同批次或同处理规则影响哪些条目，先在受影响范围追加最多 5 条未查对应；不足 5 条则全查，并更正发现的问题。
3. 追加检查又发现同类问题、影响边界不明，或错误改变主结论时，直接全查受影响范围，必要时重新提取证据。预算不允许时，将未完成范围标为未核验，暂停依赖它的强结论。
4. 重新判断候选排序与结论，记录是否变化。修订后仍应复查，不能只更换措辞。

报告实际检查量、发现问题及扩大范围。没有统计设计时，不从抽查错误率推算整份报告的正确率。未抽查条目保持原核验状态。

`Audit log` 至少记录 `population_ids`、`critical_checked_ids`、`strata`、`targeted_sample_ids`、`random_or_systematic_sample_ids`、`selection_method`、`errors`、`expanded_scope` 和 `corrections`。覆盖量按条目计数，不能用下载文件数代替已核验论断数。

## 将证据缺口转成下一步

建立 `Gap log`。为每个 `G` 记录 `affected_claims`、`decision_impact`、`missing_evidence`、`attempts`、`outcome` 和 `next_action`。每次 `attempts` 包含实际动作、来源或命令、结果及是否缩小缺口。`outcome` 为已补足、改变判断、仍缺证据或受权限／预算阻止，不准只填“待研究”。

对每个影响选择的缺口，说明哪种结果会改变判断，以及最省成本的区分办法。优先使用当前任务已授权的材料检查、合法替代来源或可逆验证。

用具体动作替代空泛结尾。例如，缺接口版本证据时查当前官方版本或只读测试；缺方法适用条件时对照当前输入和原文条件；两种候选证据相当时说明应测哪个差异。没有访问权限时列具体来源，不让用户重新做整个搜索。

推荐阈值随行动后果变化。证据足以支持低成本试验，不表示足以支持正式部署或因果结论。分别标明推荐的是调查、试验、采用，还是暂缓重大行动。

## 输出模板与验收

正文使用以下结构，标题可按用户格式调整。这里规定逻辑内容，不要求每个任务使用完整表格。

```text
当前判断：本轮能回答什么，以及现在优先推进什么。
推荐层级：investigate / test / adopt / defer。
首选与备选：候选及支持比较的 C–E 编号，不强行选唯一第一名。
关键依据：可直达原文位置的来源，附读取范围。
成立条件：已经检查的条件和尚未检查的条件。
可能推翻判断的结果：哪条相反证据或测试结果会改变推荐。
下一步：具体输入、操作、预期输出和判断标准；标明需要的授权。
核验覆盖：关键论断已完成数／总数，其他对应已查数／总数。
未完成事项：G 编号、影响、实际补查记录及下一步。
停止原因：判断已足够稳定，或明确的时间、预算、权限、访问边界。
```

输出的 `Evidence ledger` 和 `Search and audit log` 应能从正文编号追到原始位置。`Search log` 记录实际检索式或检查动作、平台／文件、日期、发现及保留／排除理由，不能声称访问过未实际访问的平台。

关键论断完成数只计必要证据已读、转述已核对、适用性判断及推断边界已说明的条目。核验后被否定的原始转述应保留修正记录，但不能算作被支持的结论。明确区分已支持、已修正和未完成，不用一个完成比例暗示正确率。

阶段交付可以保留 `unverified` 条目，但它们不能承载确定性的主要结论。若没有依据支持正式采用，输出可为推荐调查或验证；若重大行动应暂缓，同时给出补查方案。

## 检查行为是否符合目标

以下情境用于检查 skill 的实际表现，不是预设研究结论。评估时观察 agent 如何查证、修订、比较与推进，不检查它是否复述了特定措辞。

| 情境 | 应观察到的行为 |
| --- | --- |
| 多篇报道都引用同一个实验，正文声称已获多次独立验证 | 追到共同实验，纠正独立性判断，重新评估推荐。 |
| 旧的原始方法证据清楚，新综述未取得全文 | 保留可支持的机制判断，补查现行评价，不因年份或访问失败直接排除。 |
| 有相关方法与可用输入，但没有当前项目实测 | 区分条件满足与效果未测，提出有条件的验证建议，不声称已有效，也不自动拒绝。 |
| 参考信息较多，随机抽查发现省略关键限制 | 扩大到同提取或转述批次，复核未抽中的条目及结论。 |
| 候选有明显条件冲突，另有合理替代 | 核验冲突后调整排序，推进替代，不强行推荐原候选，也不停止全部研究。 |
| 只剩不确定的线索，却要求不可逆行动 | 明确不能支持该行动，提出已授权的补查或验证步骤，不用积极推进掩盖风险。 |

人工核验应集中在可能改变决策的原始依据与价值取舍。抽查和自查只能降低风险，不替代专业判断，也不能承诺用户无需任何核查。
